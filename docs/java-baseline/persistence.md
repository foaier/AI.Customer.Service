# 客服持久化约定（2026-11-11）

客服及关联 Conversation 使用项目现有 MyBatis-Plus 与 MyBatis-Plus-Join。插入、联表、子查询、分组统计和分页均交给 ORM 生成 SQL，不再维护业务注解 SQL、SQL Provider 或 MySQL/Kingbase 插入分支。类与注解使用 import，Spring 必需依赖默认用 `@Resource`，方法保持单一职责并统一格式化。

## 数据归属与实现

客服上下文拥有建议、接待周期、认领、配置、路由、等待、跟进与可靠任务；Conversation 上下文拥有 generation、人工消息、结束证据、调查及内容评估。各自实体和 Mapper 保留在 infrastructure 所属包内，应用层通过原有领域 Repository 端口协作，不直接引用其他上下文的 Entity/Mapper。

本轮调整覆盖20个持久化/查询实现，115处单表访问改用 Entity、BaseMapperX 与 Lambda Wrapper。实体以 `@TableName` 对应实际表结构，不继承会引入不存在审计字段的公共基类。复合主键均通过完整隔离条件访问，不伪造单列 `@TableId`；领域对象与持久实体分别转换。

成员权限、接待队列、人工取消、跟进联系人、成功轮次证据和指标使用 `MPJLambdaWrapper`；COUNT、MAX、MIN 和分组由 ORM 生成。分页使用 `Page`，不拼接 LIMIT。耗时指标每批读取最多200条时间投影，Java 计算秒数，不加载全部结果或逐条补查；没有首响事实不计为零秒样本。调查历史保留失败、逻辑删除和缺失消息信息，最多101条用于识别一百轮上限之外的不完整历史。

## 事务与查询约束

更新沿用原事务边界、租户/组织条件、合法前置状态、期望版本、行锁和租约校验。版本与次数递增通过期望版本 CAS 或持锁后设置新值实现，不使用 `setSql` 或 `apply`。当前框架没有类型化行锁 API，基础设施保留固定 `FOR UPDATE` 后缀，不能为删除该后缀取消并发锁。客户端内容始终参数绑定。

首次会话或客服容量行使用 ORM 插入；唯一键竞争置于 Spring 嵌套事务内，冲突回滚保存点后继续读取和校验事实，避免金仓/PostgreSQL 的事务失败状态污染外层业务操作。初始化不覆盖已有回复权、可信绑定、租约或上线代次。

Outbox 到期扫描每批也处理已耗尽预算的事件；在同一事务转为 DEAD 并保留原错误，其余事件继续采用租约和领取代次。每次处理量受批量上限控制，避免无界批量更新。

普通 Mapper、数据源引用和序列化器用 `@Resource` 注入。仅 generation 构造时需初始化事务模板，保留有原因说明的构造注入；容量和指标仓储不再读取数据库元数据判断方言。测试装配真实 MyBatis-Plus/MPJ 代理和分页插件，复用 Spring 管理的事务连接，关闭跨语句本地缓存以免跳过行锁。生产提供条件注册的分页拦截器（已有宿主配置时复用），使用 MPJ 自动装配；排除 common 传递的另一版本分页组件，避免运行时类冲突。自动配置测试核验真实会话工厂同时加载分页与联表插件。

接待配置读取拆为版本、业务组/成员及助手路由三个职责，成员在组织范围内一次读取后分组，避免逐组重复查询。缺少表不能当作空配置返回；缺结构处理和合并迁移入口见[数据库说明](database-20261111.md)。

回归验证真实 ORM 配置读写、组织隔离、成员撤权、接单并发、版本 CAS、NULL 展会绑定、AI/人工回复权切换、消息序号、调查完整性、指标及可靠任务恢复。隔离数据库不读取业务数据库配置。编译和测试记录独立保存，不能将上一版回归结果视为本次查询改写后的结果。

ORM 不负责创建表。共享开发库未迁移，现有服务未重启。Kingbase 部署脚本保持独立；本轮未连接 Kingbase 产品实例，不将 ORM 回归表述为产品环境验收。
